### 实测结论

1. **这个应用的对外网址目前是失效的。** `https://dku-ai-club.app.workbuddy.host/` 返回 HTTP 404 + 平台页「链接已失效」；`/.cloud/` 下任何路径同样。`/.cloud/v1/ping` 返回 `404 the requested endpoint is not available`，`/.cloud/database/events` 返回 `401 invalid_client`，**真 key、假 key、不带 key 三种情况响应完全一致**，说明问题不在密钥本身，而在「这个应用当前没有对外入口」。
2. **云端数据库是活的，12 条事件完好。** `mcp__genie-baas__workbuddy_cloudservice_db_*` 这套工具绕开前端凭据直连数据面，正常返回：`events`（RLS 开）/ `site_access` / `site_settings` 三表俱在；`SELECT count(*), count(*) FILTER (WHERE status='published'), min/max(event_date) FROM events` → 总计 12、已发布 12、2024-03-25 ~ 2026-07-18。逐条 slug 与 09-19 导入的那批一致（hackdku2026、waic-2026-field-trip 等）。
   - **重要手法：前端连不上不等于数据没了。查数据用 genie-baas 的 db 工具（mode=read），不要用 curl 打 `/.cloud/**` 推断后端生死。** 我一开始用 curl 得出「凭据被吊销」的结论，方向错了。
3. **生产产物是纯静态的**（`dist/`，2026-09-19 22:37 打包）：`index.html` + `index-D_OLt_NF.js`（556 KB）+ `index-Dg3exgf7.css`（93 KB）+ images + content，共 14 MB。grep 确认产物里**无** `LOCAL_API_OFFLINE` / `127.0.0.1:54321`（本地开发后端被摇掉）、**无** node 数据库驱动、**有** `dku-ai-club.app.workbuddy.host`。
   - ⚠️ **产物比源码旧**：`src/App.tsx` 与 `src/pages/About.tsx`（23:28 删 About 的统计卡）晚于 dist（22:37）。要发布必须先 `npm run build`。用 `find src -newer dist/index.html -name "*.ts*"` 判断。
4. **`pg` 已从 dependencies 移到 devDependencies**（package.json 15:26 那版），当初发布被拒的直接理由是否随之消失**未知**，需真发一次才能确认。发布工具本身对「用户没明确要求发布」的场景要求先问再做，故本轮未试。

### 结构事实（回答天成三个问题时用到的）

- **前端静态、后端托管、后端绑域名。** SDK 的 `endpoint` 文档原文：「endpoint 是每应用发布域名，承载 `/.cloud/**`」。也就是数据面**挂在发布域名的同一台主机上**，不是独立可搬的服务；服务端按 Origin 精确匹配，所以换域名 = 后端全线被拒（读库被拒、后台不可用，公开页退回随包归档 + 一条错误提示，见 `src/lib/store.tsx` 的 catch）。
- `localdev/` 只是开发替身，不进生产构建。
- 站点用 HashRouter，静态托管上刷新任意页面都不会 404 —— 纯静态搬迁（Cloudflare Pages / Netlify）本身零障碍，卡点只在后端 Origin。
- 「自有域名 + 保留后台」目前不可兼得：平台发布沙箱不提供数据库（09-19 被拒的原因），自建后端也不在平台发布通道能力范围内。要自有域名就得另配一套数据库（Supabase 一类）并把数据层换过去。

### 天成 2026-09-21 的决定

**「自有域名是必须的。」** 这一条等于排除了平台发布通道——平台给的是创建时预留的子域 `<prefix>.app.workbuddy.host`（无更换/绑定自有域名的入口），且数据面按 Origin 精确匹配只认它。**结论：站点要独立部署。** 但「必须 Cloudflare」不成立，要拆成两层：

- **静态托管**（网页那半层）随便挑：Cloudflare Pages / Vercel / Netlify / 学校服务器都可以，纯静态、HashRouter、绑自有域名都支持。
- **数据库**（真正要做的决定）：现在在平台托管库里，换域名就连不上（Origin 拒绝）。两条路——
  - **Supabase 免费档**：接口形状与现有代码几乎一致（现用 SDK 的 `Database` 类型就是照 Supabase 形状写的，`cloud.database.from().select()` / `.rpc()` 同名同形），数据层基本等价替换，改动最小。**首选。**
  - **Cloudflare Pages + D1 + Workers**：完全自控、不受第三方额度限制，但 D1 是 SQLite、接口形状不同，数据层要重写，工作量更大。

「一把站点密钥 + SECURITY DEFINER 函数」这套后台设计**与平台无关**，换后端时照搬即可（Supabase 原生支持 Postgres 函数与 RLS，正是这套设计原本参照的对象）。

数据已可随时导出（用 `db_exec_sql` mode=read 直读三张表，零转录风险）：12 条 events（含正文与 gallery）+ site_settings（当前空表）+ site_access（只有哈希，迁库时要重新种一份新密钥哈希）。
